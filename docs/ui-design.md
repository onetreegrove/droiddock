# DroidDock UI 设计稿说明

设计日期：2026-04-25

## 设计目标

DroidDock 面向非技术用户，因此 UI 需要隐藏命令行细节，把 `adb`、`scrcpy`、USB、无线连接、ADB Pair 等概念转化为清晰的流程和状态。

第一版 UI 不承载投屏画面。投屏画面由 `scrcpy` 独立窗口负责，DroidDock 负责设备发现、连接配置、投屏启动、会话管理和排障。

## 信息架构

主导航分为四个区域：

1. 首页
   - 工具状态
   - 快速连接
   - 当前投屏会话

2. 设备
   - USB 设备
   - 无线设备
   - 最近连接
   - 设备别名

3. 连接向导
   - USB 连接
   - USB 转无线
   - ADB Pair 配对

4. 设置
   - 自动安装工具
   - 手动配置 `adb` 路径
   - 手动配置 `scrcpy` 路径
   - 工具版本和诊断日志

## 核心界面

### 首次启动

目标：让非技术用户明确当前缺什么、下一步要做什么。

关键模块：

- `adb` 状态
- `scrcpy` 状态
- 自动安装按钮
- 手动选择路径按钮
- 安装来源和安全说明

### 主控台

目标：快速看到设备、连接状态和投屏会话。

关键模块：

- 顶部工具状态
- 左侧设备列表
- 中部连接方式选择
- 右侧当前会话
- 底部过程日志

### ADB Pair 配对

目标：降低 pair/connect 两个端口的理解成本。

界面必须分开：

- 配对地址和配对端口
- 配对码
- 连接地址和连接端口

界面文案强调：

- 配对码不会保存。
- 配对端口和连接端口通常不同。
- 配对成功后还需要连接。

### 多设备会话

目标：允许同时管理多台手机投屏。

每个会话展示：

- 设备名
- 连接方式
- 投屏状态
- scrcpy 窗口状态
- 停止按钮
- 重连按钮
- 日志入口

## 视觉原则

- 工具型应用，不做营销页。
- 控件密度适中，优先清晰和可扫描。
- 主色使用绿色，表示可连接和运行状态。
- 警告使用琥珀色。
- 错误使用红色。
- 设备和会话状态使用稳定色块，减少用户判断成本。
- 不使用大面积渐变、装饰性图形或复杂动效。

## 状态文案

建议把底层错误转译成用户可执行文案。

| 底层状态 | UI 文案 |
| --- | --- |
| `unauthorized` | 请解锁手机，并在手机弹窗中允许 USB 调试 |
| `offline` | 设备已离线，请重新插拔数据线或重新连接无线调试 |
| `Connection refused` | 无线调试端口不可用，请检查 IP、端口和手机无线调试是否开启 |
| `failed to authenticate` | 配对失败，请重新生成配对码后再试 |
| `more than one device/emulator` | 当前有多台设备，请先选择要投屏的手机 |
| `adb: unknown command pair` | 当前 adb 版本不支持无线配对，请升级 Platform Tools |
