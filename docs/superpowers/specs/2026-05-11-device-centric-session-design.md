# DroidDock Device-Centric Session Design

日期：2026-05-11

## 1. 背景

当前 DroidDock 已经具备基础投屏会话能力：前端可以启动 `scrcpy`、查看会话列表、停止单个会话、停止全部会话，并按会话读取 stdout / stderr 日志。后端 `SessionManager` 也已经保存 `session_id`、设备 serial、别名、PID、连接方式、启动参数和最近日志。

但当前信息架构把“投屏会话”放成独立主页面。用户从设备详情启动投屏后会跳转到会话页，导致日常操作心智从“我正在操作这台设备”切换成“我正在管理一条会话记录”。在第一版每台设备最多一个运行中会话的约束下，这个跳转和独立页面会显得偏重，也削弱了设备页作为主工作台的连续性。

本次设计目标是把投屏操作重新收敛到设备详情中：用户按设备理解和控制投屏，系统继续按会话管理 `scrcpy` 子进程、日志和参数快照。会话页保留，但定位从主操作页调整为多设备总览与批量控制页。

## 2. 目标

- 设备页成为投屏主工作台。
- 设备列表直接展示每台设备的投屏状态，让用户不用进入会话页就能知道哪台设备正在投屏。
- 设备详情内嵌当前设备的会话控制区，承载启动、停止、重连、日志和参数摘要。
- 启动投屏成功后停留在当前设备详情，不再自动跳转到会话页。
- 会话页改成“投屏总览”，保留多设备查看、停止全部、查看日志、跳转设备详情能力。
- 保留现有后端会话模型，不把会话概念从系统中删除。

## 3. 非目标

- 不嵌入 `scrcpy` 投屏画面。
- 不支持同一设备同时启动多个投屏会话。
- 不在本轮实现完整会话状态机和诊断规则库。
- 不改动 `scrcpy` 参数生成规则。
- 不改变全局默认参数、设备独立参数、会话临时参数的合并优先级。
- 不引入 Vue Router。
- 不重构 Tauri 后端会话管理，只在前端复用已有 `sessions` store 和 command。

## 4. 推荐方案

采用“设备主导 + 会话总览保留”的方案。

1. 设备页作为日常主入口。
   - 用户选择设备后，在详情中完成参数编辑、启动投屏、停止投屏、查看日志。
   - 设备列表展示投屏状态 badge。
   - 设备详情展示当前设备的会话摘要。

2. 会话页保留为全局总览。
   - 用于多设备同时投屏时查看全部状态。
   - 保留“停止全部”。
   - 每个会话卡片增加“查看设备”动作，点击后回到设备页并选中对应设备。

3. 会话模型继续作为底层事实来源。
   - `store.activeSession(serial)` 判断设备是否投屏中。
   - 新增或复用 `latestSession(serial)` 判断设备最近一次停止或失败会话。
   - 会话日志仍按 `session_id` 读取和展示。

结论：用户界面以设备为中心，后端和状态模型仍以会话为中心。这样可以降低普通用户理解成本，同时保留多设备和诊断扩展空间。

## 5. 信息架构

主导航仍保留四页：

- 设备：主工作台。展示设备列表、设备详情、设备参数、当前会话和启动/停止投屏。
- 投屏总览：跨设备会话总览。展示所有运行中、失败、最近停止会话，支持停止全部和跳转设备。
- 工具配置：adb / scrcpy 路径、版本、安装和手动配置。
- 参数设置：全局默认投屏参数。

侧栏原“投屏会话”建议改名为“投屏总览”。如果保持原名，页面标题也应突出总览定位，避免让用户误以为投屏必须进入该页操作。

设备页内部结构：

```text
设备页
├── 设备列表
│   ├── 设备连接状态：可用 / 待授权 / 离线
│   ├── 连接方式：USB / ADB Pair / USB 转无线 / 手动
│   └── 投屏状态：投屏中 / 投屏失败 / 最近停止
└── 设备详情
    ├── 设备基础信息
    ├── 当前会话
    │   ├── 未投屏：提示当前未启动投屏
    │   ├── 投屏中：PID、运行时长、生效参数、停止、日志
    │   └── 失败/已停止：最近结果、错误信息、重新投屏、日志
    ├── 投屏参数
    ├── 命令预览
    └── 启动/重连投屏按钮
```

## 6. 状态规则

设备投屏状态来自会话 store，而不是写入设备记录。

优先级：

1. 当前设备存在 `status === 'running'` 的会话：显示 `投屏中`。
2. 当前设备最近一条会话为 `failed`：显示 `投屏失败`。
3. 当前设备最近一条会话为 `stopped`：显示 `最近停止`。
4. 没有会话：不显示投屏状态 badge。

会话选择规则：

```ts
activeSession(serial) = sessions.find(session.serial === serial && session.status === 'running')
latestSession(serial) = sessions.filter(session.serial === serial).sort(started_at desc)[0] ?? null
displaySession(serial) = activeSession(serial) ?? latestSession(serial)
```

设备状态和投屏状态必须分开展示：

- `离线 + 投屏中`：理论上会话可能还未刷新退出状态，显示时应以会话状态为准，同时保留设备离线提示。
- `待授权 + 最近失败`：设备连接问题和投屏失败都应可见。
- `可用 + 投屏失败`：允许用户直接重新投屏。

## 7. 交互流程

### 7.1 启动投屏

旧流程：

```text
设备详情 -> 启动投屏 -> 自动跳到投屏会话页
```

新流程：

```text
设备详情 -> 启动投屏 -> 停留设备详情 -> 当前会话区显示投屏中
```

启动成功后：

- 刷新 sessions。
- 保持 `currentPage === 'devices'`。
- 保持 `selectedSerial` 不变。
- 当前会话区显示 PID、连接方式、生效参数和日志入口。
- 底部主按钮根据状态变为停止投屏，或当前会话区提供停止按钮。

### 7.2 停止投屏

用户可以从两个入口停止：

- 设备详情当前会话区。
- 投屏总览页会话卡片。

停止成功后：

- 刷新 sessions。
- 设备列表 badge 从 `投屏中` 变为 `最近停止`。
- 设备详情当前会话区显示最近停止结果和日志入口。

### 7.3 重新投屏

停止或失败会话在设备详情中展示“重新投屏”。

- 在线设备：使用当前设备详情中的参数编辑结果重新启动。
- 离线无线设备：走现有重连弹窗，允许编辑连接端口，连接成功后启动投屏。
- 离线 USB 设备：提示插入 USB 后刷新，不直接启动。

### 7.4 查看日志

日志入口保留两个位置：

- 设备详情当前会话区。
- 投屏总览页会话卡片。

点击日志入口时：

- 使用 `session_id` 调用 `get_session_logs`。
- 在对应上下文展开 `LogPanel`。
- 如果当前设备最近会话为 `failed`，设备详情中的 `DeviceSessionPanel` 应自动展开该会话日志。
- 失败会话存在 `last_message` 时，应在当前会话区高亮显示，减少用户寻找错误原因的点击次数。
- 不要求本轮新增复制日志或导出诊断。

### 7.5 权限引导

当选中设备处于 `unauthorized` 状态时，`DeviceSessionPanel` 的空状态应强化手机端授权引导。

展示规则：

- 如果设备未投屏且 `device.state === 'unauthorized'`，空状态文案显示：`请在手机上允许 USB 调试授权，授权后再启动投屏。`
- 如果设备存在失败或停止会话，仍优先展示最近会话，同时保留设备详情顶部已有的待授权状态。
- 该提示不改变参数生成规则，不触发 ADB 命令，不替代设备列表中的授权提示。

### 7.6 查看设备

投屏总览页每个会话卡片新增“查看设备”动作：

```text
点击查看设备 -> currentPage = 'devices' -> selectedSerial = session.serial
```

如果该 serial 已因为无线端口变化迁移，后续应复用现有记录迁移逻辑。本轮仅按当前 `session.serial` 选中设备。

## 8. 组件设计

建议新增或调整：

- `src/components/DeviceSessionPanel.vue`
  - 设备详情中的会话控制区。
  - 输入当前设备 serial 对应的 display session。
  - 展示状态、PID、运行时间、生效参数、停止、重新投屏、日志入口。
  - 失败会话自动展开日志，并高亮最近错误信息。
  - 无会话且设备待授权时，展示手机端 USB 调试授权提示。

- `src/components/DeviceList.vue`
  - 增加投屏状态 badge。
  - 增加投屏中视觉强调。

- `src/components/DeviceDetailPanel.vue`
  - 引入 `DeviceSessionPanel`。
  - 启动投屏后不跳转会话页。
  - 当前设备投屏中时，避免重复显示两个同等主操作按钮。

- `src/components/SessionCard.vue`
  - 增加可选的“查看设备”按钮。
  - 或拆成更通用的会话摘要组件，供总览页和设备详情复用。

- `src/components/SessionsView.vue`
  - 页面标题改为“投屏总览”。
  - 保留停止全部。
  - 增加会话卡片跳转设备详情能力。

- `src/stores/sessions.ts`
  - 增加 `latestSession(serial)` getter。
  - 增加 `displaySession(serial)` getter。

- `src/stores/app.ts`
  - `startMirror` 不再强制 `ui.openPage('sessions')`。
  - 新增 `showDevice(serial)` 或复用 UI store 方法完成跳转。

## 9. 文案规则

- 设备列表 badge：
  - `投屏中`
  - `投屏失败`
  - `最近停止`

- 当前会话区标题：
  - 未投屏：`当前未投屏`
  - 投屏中：`当前会话`
  - 失败：`最近投屏失败`
  - 已停止：`最近投屏已停止`

- 操作按钮：
  - 投屏中：`停止投屏`
  - 在线且未投屏：`启动投屏`
  - 失败或停止后：`重新投屏`
  - 离线无线：`重连投屏`

文案应面向非技术用户，避免只显示 `scrcpy exited with ...` 作为唯一说明。原始信息可以保留在日志中。

- 当前会话区空状态：
  - 普通未投屏：`这台设备当前没有投屏会话。调整参数后可直接启动投屏。`
  - 待授权：`请在手机上允许 USB 调试授权，授权后再启动投屏。`

- 失败信息：
  - 优先显示 `last_message`。
  - 使用错误态样式高亮，但保留原始日志入口。

## 10. 验证要求

前端改动后至少运行：

```bash
npm run test
npm run build
```

如果只修改前端 store / Vue 组件，Rust 测试不是必须项。若改动 Tauri command 或 `src-tauri`，再运行：

```bash
cd src-tauri && cargo test
```

需要人工或浏览器验证的关键流程：

- 设备列表能显示投屏中状态。
- 启动投屏后仍停留设备详情。
- 当前会话区能停止投屏并展示最近停止状态。
- 投屏失败时，设备详情能自动展开最近失败会话日志并高亮错误信息。
- 设备处于 `unauthorized` 且无会话时，当前会话区能提示用户在手机上允许 USB 调试授权。
- 投屏总览页能跳回对应设备详情。
- 日志入口在设备详情和总览页都能打开。

## 11. 风险与取舍

- 设备页会变得更重，需要控制布局密度，避免把参数编辑、会话日志和设备信息堆成一个大卡片。
- 投屏总览页如果保留过强主入口，会继续分散用户心智；页面标题和动作应强调“总览”和“批量控制”。
- `latestSession` 只基于当前运行期间的内存会话；App 重启后历史会话不存在。这与当前后端模型一致，本轮不引入持久化会话历史。
- 如果后续实现完整诊断中台，`DeviceSessionPanel` 应复用诊断结果，不应重新发明一套错误判断。

## 12. 验收标准

- 从设备详情启动投屏后不会自动切到投屏总览页。
- 正在投屏的设备在设备列表中有明确 `投屏中` 状态。
- 选中投屏中的设备时，设备详情能看到当前会话、PID、生效参数、停止和日志入口。
- 停止或失败后的最近会话仍能在设备详情中查看日志。
- 选中失败会话所在设备时，日志自动展开，最近错误信息有明显错误态展示。
- 选中 `unauthorized` 且无会话的设备时，当前会话区显示手机授权引导。
- 投屏总览页仍能查看所有会话并执行停止全部。
- 投屏总览页可以一键跳回对应设备详情。
