# 2026-05-11 设备详情页 (DeviceDetailPanel) 优化设计稿

## 1. 背景
当前的设备详情页信息密度较高，设备身份、连接状态和错误提示混杂在一起，缺乏清晰的视觉层次。用户反馈“连接状态与身份”是该页面最重要的信息。本项目旨在通过重构详情页顶部的 Hero 区域，提升视觉清晰度、交互便捷性和异常处理的引导性。

## 2. 目标
- **视觉强化 (Visual)**：明确区分 USB 和无线连接，突出设备身份。
- **交互强化 (Interaction)**：使设备别名编辑更直观、触手可及。
- **引导强化 (Guidance)**：将底层状态（如 `unauthorized`, `offline`）转译为可操作的引导横幅。

## 3. 详细方案

### 3.1 顶部 Hero 区域重构
目前的 Hero 区域信息排列较为平铺。新方案采用左侧图标 + 右侧双行信息的结构。

- **图标区**：
  - 使用 56x56 的深色卡片背景。
  - 主图标显示设备类型。
  - 右下角叠加小图标（Badge）显示连接介质：
    - **USB**：线缆/插头图标。
    - **无线**：信号/WiFi 图标。
- **信息区**：
  - **第一行**：设备别名 (Alias) 为主标题，字号 22px。
    - 点击别名可直接触发编辑逻辑（复用目前的 `handleEditAlias`）。
    - 紧随其后展示状态 Chip（如“可用”、“待授权”、“离线”）。
  - **第二行**：辅助信息，灰色字号 13px。
    - USB 设备格式：`型号 • USB • 序列号`。
    - 无线设备格式：`型号 • 无线来源 • IP/endpoint • 序列号`。
    - 这里必须保留无线 IP 或 endpoint 信息，避免移除旧 `metadata-grid` 后削弱无线重连排障能力。
  - **长文本处理**：
    - 设备别名单行省略，不能挤掉编辑按钮和状态 Chip。
    - 第二行允许换行，长 serial / endpoint 使用 `overflow-wrap: anywhere` 类似策略处理。

### 3.2 智能引导横幅 (Smart Banner)
移除目前散落在页面各处的 `device-warning` 和 `launchHint` 文本，统一为详情页顶部的横幅。

- **展示条件**：当设备状态非 `device` 或在线状态为 `offline` 时。
- **视觉风格**：
  - **待授权 (unauthorized)**：橙色背景，左侧警告图标。
  - **离线 (offline)**：红色/灰色背景。
- **文案与操作**：
  - 明确告知用户“发生了什么”以及“怎么做”。
  - 待授权文案直接给出完整步骤：“请解锁手机，在 USB 调试授权弹窗中勾选‘一律允许使用这台电脑进行调试’，然后点击允许。”
  - 本轮不增加“查看图文指引”按钮，也不使用浏览器弹窗作为占位帮助；如果后续要做帮助入口，应单独设计真实 guide modal 或跳转。
  - 无线离线且存在 endpoint 时，横幅按钮显示“重连”，只负责打开重连弹窗并恢复连接，不自动启动投屏。
  - 无线离线且不存在 endpoint 时，不展示横幅操作按钮，文案提示重新配对或通过 USB 转无线。
  - USB 离线时，不展示横幅操作按钮，文案提示重新插入 USB 数据线并确认手机解锁授权。

### 3.3 底部启动条 (Launch Bar)
- 保持底部固定，继续作为唯一“启动投屏 / 重连投屏”入口。
- 行为边界：
  - USB 在线且已授权：按钮显示“启动投屏”。
  - 无线在线且已授权：按钮显示“启动投屏”。
  - 无线离线且有 endpoint：按钮显示“重连投屏”，打开重连弹窗时携带 `launchAfterConnect = true`。
  - 无线离线但没有 endpoint：按钮禁用，提示重新配对或通过 USB 转无线。
  - 待授权：按钮显示“启动投屏”并禁用，Title 提示先在手机上允许 USB 调试授权。
- 横幅的“重连”和底部的“重连投屏”必须保持语义差异：前者只恢复连接，后者恢复连接后继续启动投屏。

## 4. 技术实现建议

### 4.1 组件拆分
为了保持代码整洁，建议将 Hero 区域和状态横幅抽离为子组件：
- `DeviceHero.vue`: 处理图标、标题和基础信息。
- `DeviceStatusBanner.vue`: 根据 `device.state` 和 `device.presence` 计算展示文案。

### 4.2 状态管理
- 复用 `useAppStore` 中现有的设备状态数据。
- 确保 `deviceIpAddress` 和 `wirelessSourceLabel` 等工具函数能够准确驱动 UI。
- `DeviceStatusBanner` 可以使用 `useUiStore().openReconnectModal(...)` 打开重连弹窗，但横幅按钮必须传入 `launchAfterConnect = false`。
- `DeviceDetailPanel` 继续持有 `canReconnectAndLaunch`、`launchButtonText`、`launchHint` 和 `launch()` 逻辑，避免启动行为分散到子组件。

## 5. 验收标准
- 用户能在一秒内区分当前是 USB 还是无线连接。
- 修改别名的操作次数减少（通过点击标题）。
- 出现 `unauthorized` 错误时，用户能明确知道下一步操作是看手机。
- 无线设备的 IP 或 endpoint 在详情顶部仍然可见。
- 无线离线且有 endpoint 时，横幅“重连”和底部“重连投屏”的行为不同且文案清楚。
- 长别名、长 serial、长 endpoint、窄宽度详情面板下没有重叠、挤压或横向溢出。
- 实现完成后需通过 `npm run test` 和 `npm run build`。
