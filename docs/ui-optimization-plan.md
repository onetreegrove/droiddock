# DroidDock UI 优化计划书

**版本：** 1.0
**日期：** 2026-05-08
**状态：** 待执行

## 1. 背景与目标
当前 DroidDock 已完成核心功能闭环，但在用户体验（UX）和视觉表现（UI）上仍有提升空间。本项目旨在通过四个阶段的迭代，将 DroidDock 从“工具型原型”提升为“专业级桌面应用”。

**核心目标：**
- **降低门槛：** 隐藏技术细节，使用户能直观理解设备状态。
- **提升效率：** 优化核心路径（投屏启动、无线连接）。
- **专业美感：** 深度适配 macOS 视觉规范，提升品牌信任感。

## 2. 优化路线图

### 阶段 P0：基础规范与可读性 (优先级：最高)
*   **痛点：** 字号偏小（10-11px）、信息密度过载、技术术语过多。
*   **任务清单：**
    - [ ] **全局排版调整**：
        - 基础字号提升：`13px` -> `14px`。
        - 次要字号提升：`10px` -> `12px`。
        - 增加行高与段落间距。
    - [ ] **列表降噪**：
        - 侧边栏设备列表隐藏 Serial 号。
        - 移除冗余的 Chip 标签，仅保留状态与连接方式。
    - [ ] **色彩系统优化**：
        - 调整 `green`、`yellow`、`red` 的对比度，确保在深色背景下符合 WCAG 可访问性标准。

### 阶段 P1：信息架构重构 (优先级：高)
*   **痛点：** 缺乏全局视角、核心连接入口过深。
*   **任务清单：**
    - [ ] **新增 Dashboard (首页)**：
        - 工具链状态卡片 (ADB, Scrcpy)。
        - 快速连接按钮阵列。
        - 活跃会话实时状态。
    - [ ] **导航结构调整**：
        - 侧边栏新增“首页”项。
        - 将“连接向导”逻辑从列表底部抽离，作为独立页面或首页核心模块。
    - [ ] **侧边栏底部精简**：
        - 隐藏版本号，通过悬浮或“关于”页面展示。

### 阶段 P2：macOS 原生化适配 (优先级：中)
*   **痛点：** 浏览器套壳感强、交互不符合 macOS 习惯。
*   **任务清单：**
    - [ ] **Vibrancy 毛玻璃**：
        - 开启侧边栏透明模糊效果。
        - 适配 macOS 窗口控制按钮（交通灯）位置。
    - [ ] **自定义 Modal 系统**：
        - 开发 Vue Modal 组件，替换 `window.confirm` 和 `window.alert`。
        - 支持背景遮罩平滑淡入和卡片缩放动画。
    - [ ] **拖拽区域优化**：
        - 确保顶部标题栏拖拽区域响应灵敏且不遮挡按钮。

### 阶段 P3：功能闭环与交互增强 (优先级：低)
*   **痛点：** 别名不可修改、错误报错难懂、缺乏过渡动效。
*   **任务清单：**
    - [ ] **设备别名管理**：
        - 在详情页增加“修改别名”入口。
        - 实现前端持久化存储（同步至后端配置）。
    - [ ] **智能错误引导**：
        - 建立错误转译库。
        - 针对 `unauthorized` 等错误弹出引导式 Dialog，而非仅显示文本。
    - [ ] **动效注入**：
        - 页面切换淡入淡出。
        - 列表刷新时的加载反馈（骨架屏或 Loading）。

## 3. 验收标准
1.  **首屏加载**：用户打开应用后 1 秒内能明确判断 ADB 工具是否可用。
2.  **可读性**：在不缩放情况下，50cm 距离外能清晰识别设备型号。
3.  **一致性**：所有弹窗风格统一，不再出现浏览器原生提示框。
